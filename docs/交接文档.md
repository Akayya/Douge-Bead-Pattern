## 0. 一句话说清这是什么

一个**纯离线**的安卓「拼豆」辅助 App：把照片/截图转成拼豆图纸、手工绘制、统计豆数与成本、按图纸施工打勾、导出 PNG 与 A4 PDF。
只给作者自己用（不发布商店、不做账号/社区/云同步）。

- App 名：**豆格**
- 包名 / applicationId / namespace：`com.pindou.app`（历史原因保留，改名等于换 App，旧数据不跟随）
- 语言：Kotlin + Jetpack Compose，全部界面代码手写，不引 Room、不引 kotlinx.serialization

### 2.4 想点某个按钮时，别靠肉眼算坐标

这是本项目**最浪费时间**的一件事。屏幕 1080×2400，而我看到的界面预览图是 838 宽，手算 `×1.289` 经常差几十像素，结果点到相邻控件上、或点空。

**唯一可靠做法**：

```powershell
& $adb shell uiautomator dump /sdcard/ui.xml | Out-Null
$xml = & $adb shell cat /sdcard/ui.xml
[regex]::Matches($xml, 'text="开始施工"[^>]*bounds="\[(\d+),(\d+)\]\[(\d+),(\d+)\]"') | ForEach-Object {
  $cx = ([int]$_.Groups[1].Value + [int]$_.Groups[3].Value)/2
  $cy = ([int]$_.Groups[2].Value + [int]$_.Groups[4].Value)/2
  Write-Output "$cx,$cy"
}
& $adb shell input tap $cx $cy
```

## 4. 数据与存储（都是纯 JSON 文件，没有数据库）

| 文件 | 内容 | 谁在写 |
|---|---|---|
| `files/patterns/<id>.json` | `{v, id, name, w, h, paletteId, createdAt, updatedAt, cells: IntArray, done: IntArray}` | `PatternStore` |
| `files/palettes/<id>.json` | 自定义色板：`{id, title, groups, colors:[{code,hex,g}]}`，id 形如 `custom-<base36时间>`，最多 500 色 | `PaletteStore` |
| `files/palette_state.json` | `{active: "mard221", disabled: {"mard221":["A4", …], "custom-xxx":[…]}}` | `PaletteStore` |
| `files/palette_calibrated.json` | `{"mard221":{"F2":"#00FF00"}}`，只存改过的色号 | `PaletteStore` |
| `files/inventory.json` | `{"mard221":{"A19":100}}`（**没有键 = 不追踪**） | `InventoryStore` |
| `files/inventory_deductions.json` | `{"<图纸id>": <扣减时间戳>}`，表示这张图已经扣过库存 | `DeductionStore` |
| `files/cost.json` | `{pricePerBead: 0.02, minutesPer100: 5}` | `CostSettings` |
| `files/thumbs/<id>-<尺寸>-<色板>-<颜色指纹>-<cells哈希>.png` | 256px 库页缩略图缓存，可随时删 | `PatternThumbCache` |
| `files/snapshots/snap-<时间戳>.zip` | 本机自动/手动快照，格式同整库备份；最多 5 份，不进入导出的备份包 | `SnapshotStore` |
| 用户选择的 zip | `manifest.json` + `patterns/*.json` + `palettes/*.json` + 五个设置文件（含 `inventory_deductions.json`）；格式 v2 整库备份，不放进 `filesDir` | `BackupManager` |
| 用户选择的 `.json` | 单张图纸分享文件：`app/format/kind` 标记 + `paletteId` + 用到的色号表 `colors` + 内嵌 `pattern`；自定义色板另有完整 `palette` 对象；导入后写到 `files/patterns/<新id>.json` | `PatternFile` |
| `cacheDir/share/` | 分享前的临时 `.json`，每次分享前清空，可随时删 | `PatternFile` |
| `shared_prefs/library_prefs.xml` | `<string name="sort">Updated</string>`（最近更新/最近创建/名称/豆数） | `LibraryScreen` |

`cells` 里存的是**色板下标**，`-1` 表示空位（不放豆）。
⚠️ 历史坑：`#FFFFFF`（纯白）的 Int 值恰好是 `-1`，所以任何"无效/透明"哨兵**必须用 0 或 -2，绝不能用 -1**（README 坑 13）。

备份/恢复要点（`data/BackupManager.kt`）：
- 导出走 SAF `CreateDocument`，导入走 `OpenDocument`，不需要存储权限；zip 内含 9 张图纸时约 10 KB（无自定义色板）。
- 格式 v2（0.6.20 起）在 `patterns/` 之外增加 `palettes/<id>.json`，manifest 带 `paletteCount`；v1 包仍可读。导出前会校验每张图纸引用的色板都存在、每个格子下标都在色板范围内。
- 合并导入不删现有数据：同编号图纸另存副本（名称加「（导入）」）；库存/校准只补本地缺失色号；色板开关和成本只在本地文件不存在时采用备份值。自定义色板按 id 合并：本地缺就写入；同 id 内容一致跳过；同 id 颜色不同整包拒绝，避免图纸色号错位。
- 覆盖恢复先校验全部图纸、色板和设置，再把 `patterns`/`palettes` 两个目录整体替换，最后替换设置文件；会清空 `files/thumbs`。导入完成后必须调用 `PaletteStore.reload()` / `InventoryStore.reload()` / `DeductionStore.reload()` / `CostSettings.reload()` 并重读图纸列表，否则界面还是旧数据。合并导入不搬 `inventory_deductions.json`（可能多问一次，不会自动重复扣）。
- v1 旧包没有 `palettes/`：合并导入保留本机自定义色板；覆盖恢复按整库替换语义会清空本机自定义色板，替换后若图纸引用了不存在的自定义色板会被校验拦截。
- zip 只接受 `manifest.json`、五个设置文件、`patterns/<安全 id>.json` 和 `palettes/<安全 id>.json`；目录穿越、超大条目、损坏图纸/色板都会中止整次导入。
- 本地快照（0.6.18）复用同一 zip 格式，存在 `files/snapshots/`，**不放进导出的备份包**。启动时若数据在上次快照后变过且上一份已超过 6 小时，自动留一份；删除图纸前、覆盖恢复前也会先留一份。最多保留 5 份，超出删最旧；恢复来源文件在裁剪时受保护，避免边恢复边被删。恢复快照走覆盖导入路径，恢复前自动给当前数据留安全快照，创建失败则中止恢复。自定义色板文件也计入数据变更判断。
- 材料单 CSV 走 MediaStore 写 `Download/豆格/豆格-材料单-<图纸名>-<时间>.csv`，带 UTF-8 BOM 与 CRLF；没记过库存的色号，库存/缺口留空，不按 0 算。`MaterialListCsv.buildCsv()` 是纯函数，可直接单测。
- 库存 CSV 导入走 SAF `OpenDocument`，`InventoryCsv.parse()` 只做解析与分类（可导入 / 未识别 / 无效行），预览确认后 `InventoryStore.setAll()` 一次写入并落盘。空数量不覆盖原值；“没有键 = 不追踪”的规则保持不变。文件读取先严格 UTF-8，失败回退 GB18030，上限 2 MB。
- 拼完扣减规则（`data/InventoryDeduction.kt` + `ui/build/BuildModeScreen.kt`）：只在施工进度到 100% 时提示；用户确认后才扣；只扣 `InventoryStore.count() != null` 的色号，库存不足扣到 0，不产生负数；`DeductionStore` 按图纸 id 记“已扣”，每张图只扣一次，重启/再次完成都不重复。标记先于库存落盘，崩溃时最多少扣。标记文件随整库备份导出和覆盖恢复；合并导入不搬这个标记（可能多问一次，不会自动重复扣）。
- 单图分享/导入（`data/PatternFile.kt`）：分享走 `ACTION_SEND`（`application/json`）+ FileProvider，临时文件写到 `cacheDir/share`（每次分享前清空），文件名取 `豆格图纸-<安全名>-<时间>.json`。导入走库页「导入」的 SAF `OpenDocument`，按内容校验、不看扩展名。包装格式 `{app:"douge", format:1, kind:"pattern", versionName, exportedAt, paletteId, colors:{色号:HEX}, pattern:{...}}`；自定义色板额外带 `palette:{id,title,groups,colors}`，内置色板不带。导入**永远分配新 id**，不覆盖、不合并现有图纸；重名依次加「（导入）」「（导入） 2」。文件损坏、`app/kind/format` 不对、出现本地色板没有的色号都会拒绝且不落盘。自定义色板导入时：同 id 内容一致直接复用；同 id 内容不同或本地没有，则按颜色找已有自定义色板复用，否则新建一份并把图纸 `paletteId` 重映射到本地 id（格子下标不变），成功提示会附带「同时导入色板」。`colors` 只用于对照：来源色号颜色与本地校准后颜色不同时提示「N 个色号颜色不同」，不阻断导入。读取上限 32 MB，UTF-8（容忍 BOM）。
- 自定义色板（`data/Palette.kt` + `data/PaletteCsv.kt` + `ui/palette/PaletteScreen.kt`）：CSV 通过 SAF 读取，先严格 UTF-8 再 GB18030，上限 2 MB；表头识别中英文色号/HEX 列，无表头取前两列；色号 `[\p{L}\p{N}_-]{1,16}` 统一大写，HEX 规范为 6 位；重复色号/非法行计数，最多 500 色。确认后 `PaletteStore.importCustomPalette` 写 `files/palettes/<custom-…>.json` 并切换；`deleteCustomPalette` 会清理文件、校准、库存键和开关记录，当前色板被删时回落到 MARD 221。有图纸引用时 UI 禁止删除。

## 5. 核心算法（改之前先看懂这三段）

### 5.1 认原图网格 `data/PixelGrid.kt`
像素画的格子边界是等距的。对"逐列相邻像素差"求和得到边缘能量曲线 → 自相关找周期 → 取相位找第一条边界 → 得到 `cellX/cellY/offsetX/offsetY/cols/rows`。

必须注意的三点：
- **周期要细化到 0.05px**：截图缩放常让格子不是整数（实测 27.3px），取整后累积 50 格就是半格漂移，右边整片取错色。
- **照片必须能干净地判失败**（0.6.21）：只看自相关置信度不够，平滑渐变的照片也会在 2px 处给出 0.99 的峰。现在要求周期 ≥3px、格数 ≤240（超了直接失败，**不要截断**）、边界能量集中度 ≥1.5（真实网格实测 3+，照片 1.0–1.2）、且 x/y 周期差 ≤1/4 格。裁剪区大于 1024×1024 时只扫中心+四角五个窗口，再把相位换算回整块裁剪区。
- 置信度不足（照片、无网格）返回 `null`，上层退回"长边格数"缩放模式。

### 5.2 取色成图 `data/ImageToPattern.kt`
1. 按网格**逐格 1:1 采样**，每格四边各收进来 18%（只取中间 64%），避开边界过渡色；
2. **每格取主色**（占比过半），主色不过半才退回平均色——这是"细小处出现灰块"的根因修复；
3. 在**「我有」的色号**里找最近色（加权距离 `2R²+4G²+3B²`，带 RGB 缓存）；
4. 按用量挑前 N 色时，与已选色距离 < 2400（约每通道差 16）的直接并过去，否则十几个"几乎一样的白"会把色数预算吃光；
5. 被砍掉的色号改投到最近的保留色。

采样前会按输出格数把大图缩到「每格约 8×8 个点」（绝对上限 2M 像素），裁剪与缩放用一次 `createBitmap(source, left, top, w, h, matrix, true)` 完成。4096×3072 原图整张读像素是 50MB `IntArray`，手机上会 OOM；别改回「先整张裁剪再单独缩放」。

### 5.3 去杂点 `data/PatternCleaner.kt`
只看 8 邻域，但**多一道颜色闸门**，满足其一才清：
1. 与主邻居色几乎同色（加权距离 < 1300）；
2. 颜色落在「主邻居色—次邻居色」连线上（偏差 ≤ 18%）——两色混出来的过渡色。

黑画在白上、白画在黑上这类对比色孤点**两个条件都不满足，一律保留**。
> 第一版只看"孤立不孤立"，把黑眼珠/线条端点也并了，表现成"黑色被平均成灰色"。**孤立 ≠ 噪点。**

### 5.4 图形边界 `data/ShapeBoundary.kt`
取四边众数色当背景 → 从四边洪水填充标记"图外" → 图外置空 → 再对紧贴图外的一圈做"稀有混色吸附"。被描边围住的白色（白毛、白底块）与背景不连通，所以**不会被误删**——这是它比"去杂点"重要的地方。

### 5.5 拼豆板布局 `data/BoardLayout.kt`
纯数学、无 Android 依赖：板尺寸只认 29 或 58（其它值回退 29）；板数 = `ceil(宽/板宽) × ceil(高/板高)`，板号按行优先；`bounds()` 返回某块板的起始列/行与实际宽高，右边/下边不足一板时裁剪。施工页的板号过滤、逐板进度和跨板跳转都用它。A4 PDF 的分页规则与它一致（29 模式一页一块、58 模式一页 2×2），但代码是分开写的，改板尺寸规则时两处都要看。

### 5.6 本地快照策略 `data/SnapshotPolicy.kt`
纯函数、无 Android 依赖：`shouldAutoSnapshot(now, newestAt, latestChangeAt)` 在「没有快照」或「数据在上次快照后变过且上一份超过 6 小时」时返回 true；`namesToDelete(names, keep, protect)` 按从新到旧保留前 5 份，并额外保留正在恢复的来源文件。`SnapshotStore` 用文件修改时间判断数据变更，快照文件名为 `snap-<epoch millis>.zip`；扫描时按 manifest 判定有效，损坏文件不会进入列表但仍会按文件名参与裁剪。改保留份数或自动间隔这两处即可，UI 文案在 `SnapshotCard.kt`。

## 6. 硬约束（违反会编译失败或有隐蔽 bug）

1. **不要应用 `org.jetbrains.kotlin.android` 插件**。AGP 9 内置 Kotlin 2.2.10，再应用会报 `Cannot add extension with name 'kotlin'`。只加 `org.jetbrains.kotlin.plugin.compose`。
2. **不要引 Room / kotlinx.serialization / Hilt**。存储就是 `org.json` + 手写文件读写，这是刻意保持的轻量。
3. **改 Kotlin 源码不要用 PowerShell 的 `Get-Content`/`Set-Content`**。PS 5.1 按 ANSI 处理无 BOM 的 UTF-8，中文会变乱码、行尾引号会丢。用编辑器工具、`write`/`edit` 工具，或 Python（`io.open(..., encoding="utf-8", newline="\n")`）。
4. **批量改代码的 `replace` 必须配 `assert old in s`**。本项目真实事故：给 `AppRoot.kt` 加 `onRestore` 回调时字符串没匹配上、静默没写入，结果"撤销删除"点了没反应，排查了半小时。定位手法：`grep -n onRestore AppRoot.kt` 看是不是 0 处。
5. **改完必须装机验证**，不能只 `BUILD SUCCESSFUL` 就报完成。本项目的 bug 绝大多数是"能编译、运行结果错"。
6. **所有导出都走 MediaStore**（minSdk 30 时无需任何权限）。不要加 `WRITE_EXTERNAL_STORAGE`。
7. **interface 变更要全局搜调用点**：`PatternDetailScreen` / `LibraryScreen` 的签名改过多次，`AppRoot.kt` 是唯一装配处。
8. `android:overridePathCheck=true` 必须留着——工程路径含中文。
9. 新增界面请沿用现有风格：`TopAppBar` 手写（没有 Navigation 库）、`Scaffold` + `innerPadding`、`OutlinedButton` 成对排成两列。
10. 每完成一批功能：**更新 README 对应小节 + 升 `versionCode`/`versionName` + 提交（中文 commit message，`feat:` / `chore:` 前缀）+ push**。
11. **测试 worker 的编码**：工程路径含中文时，`gradle.properties` 必须保留 `org.gradle.jvmargs=... -Dfile.encoding=COMPAT`。Gradle 用 daemon 默认编码写 `@argfile`，JVM 启动器按系统编码读；写死 UTF-8 会让测试类路径变成乱码，报 `ClassNotFoundException`。
12. **ARGB 颜色不能拿负数当「无效」哨兵**：不透明色 `0xFF……` 在 Int 里全是负数。PatternCleaner 曾用 `argb < 0` 判断颜色无效，导致去杂点永远不生效。用可空类型或 0。
13. **JVM 单测里用 `org.json` 必须加测试依赖**：Android 的 `org.json` 在本地单测中只是抛 `Method not mocked` 的桩。`app/build.gradle.kts` 已加 `testImplementation("org.json:json:20240303")`（只影响单测，App 内仍用系统自带实现）；新增依赖 JSON 的纯逻辑测试时别删它。

## 7. 高危坑 Top 9（完整 18 条见 README「已踩过的坑」）

1. **`-1` 不能当无效值**（纯白 = -1）。
2. **`Bitmap.createBitmap` 裁剪整张图时原样返回 source**，此时 `recycle()` 会把界面上正在画的 bitmap 回收 → 崩 `trying to use a recycled bitmap`。
3. **`pointerInput(Unit)` 的 lambda 只创建一次**：其中捕获的 `val`（比如 `groupColor`）永远是首帧的值。要用 `fun` 现算，或用 `rememberUpdatedState`。这个坑导致"切到逐色视图后照样能勾别的颜色"。0.6.17 按板视图又踩了一次：`groupBoard()` 读了组合期算好的 `currentBoard`，切到 58 板后仍按旧板号过滤，而 `boardSpan` 因为直接读 state 是新的，表现为"板内点不动、长按清板无效"；已改成在 `fun` 里用 `BoardLayout.count(...)` 现算。
4. **Compose `Canvas` 默认不裁剪**：放大后绘制会溢出到画布外盖住按钮，必须 `.clipToBounds()`。
5. **`adb exec-out screencap` 必须走 `cmd.exe /c "... > file.png"`**。
6. **手势会被外层 `verticalScroll` 抢走**：需要独占手势的区域必须放在滚动容器外。
7. **读图上限别太小**：`loadBitmap(..., 4096)`；2000 会把 1440×3200 的截图砍半，网格精度直接毁掉。
8. **`uiautomator dump` 是点控件的唯一可靠方式**，别手算坐标。
9. **不透明 ARGB 都是负数**，不能拿 `< 0` 判断「查不到颜色」（见 §6 第 12 条）。

  'for y in 800 821 842; do for x in 300 321 342; do input tap $x $y; done; done' | & $adb shell sh -

## 11. 还没做、但值得做的（按性价比排序）

1. **已扣减图纸编辑后的差额**：现在每张图只扣一次，拼完后再改图（加边、改色、旋转）不会补扣新增豆子，也不会退回。要做“补扣差额”需要记录当时扣减的色号用量，规则成本较高，暂不做；需要时手动改库存。
2. **旧缩略图文件的主动清理**：现在靠同一张图纸下次渲染时按 `<id>-` 前缀删旧文件；长期不打开的图纸，旧指纹 PNG 会留在 `files/thumbs`。可加启动时按数量/时间清理（缓存本身可随时删）。
3. **网格识别对非整数倍周期**：自相关找周期时遇到 3.3px、8.5px 一格这类情况会锁到整数倍或失败（0.6.10 写单测时暴露，未改生产算法）。常见截图缩放（27.3px 等）已验证；要修需要换更细的周期估计。
4. **校准取色方式**：目前只能手输 6 位 HEX；可加系统取色器/色卡吸管，或者按色系批量校准。
5. **底图描图**：把参考图半透明垫在空白画布下面手描（§10 已明确不做自动截图识别，这是替代方向）。
