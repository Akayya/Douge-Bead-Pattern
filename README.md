## 图片转图纸怎么算的（M2）

两个文件：`data/PixelGrid.kt`（认格子）和 `data/ImageToPattern.kt`（取色成图）。

1. **认原图网格**：像素画的格子边界是等距竖线/横线。把每列相邻像素差加起来得到边缘能量曲线，对它做自相关，相关最高的位移就是格子周期，再按周期取相位找第一条边界。认出 `28×28 px 一格` 就按 `51×115` 格 1:1 采样，**不再把原图硬缩成 29 格**。截图缩放常让格子不是整数（实测 27.3px），所以周期要细化到 0.05px——差 0.3px、累积 50 格就是半格漂移，右边整片取错色。置信度不够（照片）自动退回「长边格数」模式，界面里也能手动切。
2. **每格取主色**：一格内出现次数过半的那个颜色就是这格的色，只有主色不过半（照片/渐变）才退回平均色。这一步是「细小处出现灰色色块」的根因修复——原来整图先缩放、每格取平均，细线和轮廓边缘会被平均成灰。
3. **落色号**：每格在**「我有」的色号**里找最近色（加权 RGB 距离 `2R²+4G²+3B²`，同一 RGB 只算一次，有缓存）。
4. **合并近似色**：按用量挑前 N 色时，和已选色加权距离 < 2400（约每通道差 16）的不再占用名额，直接并过去。色板里十几个近乎一样的白/黑/灰，不合并会把色数预算全吃光，还会把压缩噪点放大成一格格灰白杂点。
5. 被砍掉的色号最终改投到保留色里最近的一个。

不用 k-means：色板是几百个离散色号，最终每格必须落在真实色号上，直接以色板为聚类中心既省事又不会画出"色板上不存在的颜色"。

6. **取格心不取整格**：1:1 采样时每格四边各收进来 18%（只取中间 64%）。格子边界那一两圈像素往往是缩放/抗锯齿混出来的过渡色，整格统计会把灰边一起抄进图纸，描边外侧就拖出一圈灰。

## 去杂点与框选（M3）

- **先定位网格，再框选**（正确顺序）：选完图立刻在全图跑一次网格识别，把格子线**画在裁剪区上**（每 5 格加粗一根），提示行写「已定位网格 27.4×27.3px 一格 · 48 × 51 格」。之后拖框只框图案，**四条边自动吸附到格子线**，保证输出永远是整格。
  - 为什么要吸附：格子没对齐时每格边缘都会掺进邻格像素，黑色描边被平均成灰、细线被切掉，看起来就是「黑色变成灰色」。
  - 「按原图 1:1」模式下吸附后的成品就是源图格子数；识别不出网格（照片）时不吸附，退回「长边格数」缩放。
- **自动识别图形边界**（`data/ShapeBoundary.kt`，可选，默认开）：按图形轮廓把"图外"和"图内"分开，解决两个反向的问题——
  - 外面的空白不生成豆子：取四条边最常见的颜色当背景色，从四边向内做 4 邻域洪水填充，跟边界连通的同色格子全部置空（-1）。
  - 里面的内容一格不少：被描边围住的白色（白毛、白底块）与背景不连通，洪水填充进不去，所以不会被当空格。
  - 边界一圈的混色并回主体色：只处理"全图出现次数 ≤0.5%"的稀有颜色（说明它只是混色），并且它的颜色落在"背景色—相邻主体色"连线上（偏差 ≤20%），才并过去。大面积灰阶（阴影）用量大，不会被误伤。
  - 统计行会写「去掉背景 N 格」。关掉开关就完全跳过这一步。

- **框选裁剪**（`ui/importsheet/CropView.kt`）：在图上任意处拖一个框就能重新框选（截图工具那种），拖四角微调。抓手只在离角 20dp 内生效——44dp 时从离角 100px 的地方起手也会被抓角，拉框根本拉不出来。
- **去杂点**（`data/PatternCleaner.kt`）：只看 8 邻域，但**多一道颜色闸门**，只有两种情况才算杂点：
  1. 和主邻居色几乎一样（加权距离 < 1300，约每通道差 12）——压缩噪点；
  2. 颜色落在「主邻居色」和「次邻居色」的连线上（偏差 ≤ 18%）——两色混出来的过渡色。

  黑画在白上、白画在黑上这类**对比色孤点两个条件都不满足，一律保留**。第一版只看「孤立不孤立」，把黑眼珠、鼻子尖、线条端点也并掉了，表现成「黑色被平均成灰色」——教训：孤立 ≠ 噪点。
  - 两个入口：图片转图纸页的「自动去杂点」开关（默认开）；图纸详情页的「去杂点」按钮（轻/中/强三档，直接存盘，底部提示清掉几个）。
  - 网格对齐做好之后，样例狗图一个点都不需要清（统计行不显示「清掉 N 点」）：噪声的根源在采样对齐，不在采样之后的清理。

## 图纸小工具（M3）

- **29 格分区线**（`ui/PatternCanvas.kt` 的 `boardSize` / `boardColor` 参数）：拼豆板是 29×29，图上每 29 格画一条粗线，施工时直接对板号；57 格正好两块板。屏幕上一格太小时（`cell * 29 < 24dp`）不画，免得糊成一片。
- **库页长按菜单**：长按图纸卡片 → 重命名 / 复制一份 / 删除。复制是深拷贝 `cells` 与 `done`，两份互不影响；删除是删文件，会二次确认。
- **取豆清单**：色号明细里每色在颗数下面加一行「8×100 + 54」，按 100 颗一袋数，省得数错。
- **Android 版本**：`minSdk = 30`（Android 11）。导出用的 `MediaStore`（含 `RELATIVE_PATH` / `IS_PENDING`）和 `MediaStore.Downloads` 都从 API 29 起可用，所以降到 11 不需要额外权限或兼容分支；`PatternExporter` / `PatternPdf` 里「老系统写应用私有目录 + MediaScanner 通知」的兜底代码仍然删掉，导出统一走 MediaStore。
- **PDF 分块图纸**：A4、每页最多 36 列 × 48 行、每格 15pt 带色号，页眉标「图纸 i / N · 列 a–b · 行 c–d」，网格外圈标每 5 格的行列号，页脚标页码和「← 与左页拼接 / ↑ 与上页拼接」。空格填淡灰，打印后能一眼区分「白豆」和「不放豆」。
  - 验证方式：用 `pypdfium2` 把每页渲成 PNG 逐页看过（之前只验结构，看不到排版，属于「没测过」）。
- **施工页看色号**：施工页右上角有个「色号」开关（默认关）。打开后每颗豆子上直接标出色号（深色底用白字、浅色底用黑字），不用来回对色板。图特别大、单格小于 9px 时自动不画，免得糊成一片。
- **库页进度条**：图纸卡片上直接显示施工进度（「施工 5% 87/1667」），拼完变绿显示「已拼完」。没打过勾的图纸不显示进度条，列表保持干净。
- **开始施工**：详情页最显眼的那颗实心紫按钮，点进去就是逐行/逐色/按板施工模式。原来它挤在按钮网格里，翻半天才找到。
- **新建空白画布**：库页右下角两个按钮——「空白画布」直接从零画（填宽高，29 是一块标准板、57 是两块），「图片转图纸」走转换流程。空画布建好会直接进编辑器。
- **撤销上一步**：去杂点 / 减到 N 色 / 画布变换都会覆盖原图，所以详情页会留一份改动前的快照。执行完这些操作后，卡片上方会冒出一个「撤销上一步（回到改之前）」按钮，点一下完整回滚（包括施工进度）。只保留一步——够救命，也不至于把内存吃满。
- **画布变换**（`data/PatternTransform.kt`）：详情页「画布」→ 裁掉空白边 / 四周各加 1 格 / 顺时针旋转 90° / 水平翻转。旋转会把宽高互换（48×51 → 51×48）。这些操作都会改变格子坐标，所以**执行后施工进度会被清空**，提示里会写明。
- **导出 PNG**（`data/PatternExporter.kt`）：详情页「导出 PNG」，画出一张带标题、网格、29 格分区线和底部色号清单（色块 + 色号 + HEX + 颗数）的图，存到相册 `Pictures/豆格/豆格-<时间>.png`。
  - 不申请存储权限：minSdk 30 起直接用 MediaStore 插入图片，不需要任何存储权限。
  - 空格画成浅灰（`#F4F4F8`），跟白豆子区分得开；色块外面描一圈细边，白色色号也能看见。
- **减到 N 色**（`data/PatternReducer.kt`）：保留用量最多的 N 个色号，其余色号按加权 RGB 距离并到最近的保留色；执行前显示「会有 N 颗豆子换色号」，执行后提示「并掉 X 个色号，改动 Y 格」。总颗数不变，只换色号。


## 成本与工时（M4）

- 详情页「成本与工时」卡片：豆子单价（元/颗，默认 0.02）、工时估算（每 100 颗多少分钟，默认 5），点一下就能改，存在 `filesDir/cost.json`，全局一份。
- 卡片直接算「合计 ¥X · 预计 X 小时 X 分」；色号明细每一行也带上该色的花费，方便看哪个色最贵。
- 只是估算：真实成本还取决于你按什么价进货、拼得多快，这两个数字自己按实际改。

## A4 分页 PDF（M4）

- 详情页「导出 A4 PDF」先选分页方式：每页 29×29（单块板，格子大、印色号）或 58×58（2×2 块板，省纸、不印色号字），存到 `下载/豆格/`（不申请存储权限，走 MediaStore）。
- 第 1 页：标题 + 尺寸/颗数/色数 + 成本工时 + 分页方式 + 取豆清单（色块、色号、HEX、颗数、单价金额，两列排）。
- 后面每页按拼豆板切块，页边界与 29 格板边界对齐；格宽由纸张可用宽度反算（29 模式约 18.7pt/格，58 模式约 9.4pt/格），不足一板的末页保持同样格子大小与原点，拼页不会错位。
- 网格 + 每 29 格加粗分区线；页眉写「图纸 i / N · 列 a–b · 行 c–d · 每页 N 格」，页脚写页码和「← 与左页拼接 / ↑ 与上页拼接」。

## 编辑器（M3）

- 入口：详情页「编辑」。画布支持双指缩放（1×–8×）与平移，工具栏六种：**画笔 / 橡皮 / 油漆桶 / 吸管 / 直线 / 矩形**，另有「左右镜像」开关。
- **一次落笔算一个撤销步**：手指按下时存一份 `cells` 快照，只有真的改了格子才入栈，栈上限 30 步；一笔画过 30 个格子也只是一步，撤销不会一格一格倒退。
- 画笔沿两帧之间补线（Bresenham），画得快也不会漏格。
- **直线 / 矩形**：按住拖拽，松手才真正落格，拖动过程中画布实时预览；一次拖拽同样只算一个撤销步。矩形画的是空心边框，画完可以用油漆桶一键填色。
- **左右镜像**：开启后画笔、橡皮、直线、矩形都会同时写到左右对称的格子上，画布中间显示一条淡紫色对称轴；油漆桶按区域填色、吸管取色，不受镜像影响，避免误填到另一侧。
- **替换此色**（`replaceAll`）：先用吸管或直接点色板选源色，弹出的对话框里选目标——色板任一色或「变成空位」——按全图同色替换，执行后可撤销，提示「换掉 N 格 / 清空 N 格」。
- **选色按色系分区**（`ui/editor/ColorPickerSheet.kt`）：底部色条只放「本图用到的颜色」+ 一个「更多色」；点「更多色」弹出面板，顶部按色系分 chip（全部 / 黄 A / 绿 B / 蓝 C …），下面是色号网格，每格带色号字。这样两百多个色号不会挤成一条长条，也不用凭颜色瞎猜色号。
- 替换色号的目标色也走同一个面板（「选择目标色（按色系挑）」），不再是横着划到底。
- **色系中文名**（`PaletteGroups` in `data/Palette.kt`）：色号首字母对应色系，A 黄 / B 绿 / C 蓝 / D 紫 / E 粉 / F 红 / G 棕 / H 灰白 / M 莫兰迪；291 色里多出来的 P/Q/R/T/Y/ZG 没有官方中文名，按各组实际颜色标成 杂色 / 荧光 / 彩虹 / 单色 / 柔彩 / 珠光（描述性叫法，随时可改）。色板页的分组 chip 用「色系名 + 数量」。
- 色板只列「我有」的色号（跟色板页的开关联动）；当前画笔色如果不在本图用色里，会自动插到色条最前面，避免「选了却看不出选了哪个」。

## 施工模式（M3）

- 入口：详情页「施工」。四种视图：**全部**（整图）/**逐色**（只高亮某色，其余压暗，顶部一排色块切换）/**逐行**（逐行施工，带「上一行 / 下一行」）/**按板**（29×29 或 58×58 一块板施工，带逐板进度与上一板/下一板）。
- 点格子打勾，已打的格子中心显示一个紫色圆点（白豆子上也看得见）；长按清掉当前行（逐色视图里是当前色，按板视图里是当前板）的勾。
- 进度条 + 「已打勾 / 总颗数」实时更新。
- `done` 集合直接存在图纸文件里，改动后 500ms 防抖落盘——切走再回来进度还在。

## 体验改进（0.6.0）

- 快照复用整库备份 zip 格式，存在 `filesDir/snapshots/snap-<时间戳>.zip`；最多保留 5 份，超出自动删最旧的。快照只在本机，**不放进导出的备份包**，卸载/换机仍要另外导出备份。
- 触发时机：
  - 打开 App 时，如果数据在上次快照之后有改动、且距上一份超过 6 小时，自动留一份；刚装好第一次的示例图纸不会立刻占一份。
  - 删除图纸前自动留一份（含待删图纸）；快照失败时会提示，撤销仍然可用。
  - 覆盖恢复（导入备份）前自动留一份；快照创建失败则取消恢复，避免恢复失败还丢掉当前版本。
- 恢复快照是整库覆盖：图纸、施工进度、色板开关/校准、库存、扣减标记、成本全部回到快照时；恢复前先给当前数据留安全快照，恢复后缩略图按需重建。
- 数据变更按文件修改时间判断；阈值与保留份数在 `data/SnapshotPolicy.kt`，有 JVM 用例覆盖。
- 模拟器验证：9 张图纸启动自动生成 1 份；自动 1 份后再手动做 5 份，只保留最新 5 份；无改动重启不重复生成；删除临时图纸后快照包含 10 张，恢复后图纸与施工进度回到删除前（1/1743），再清理回 9 张；SAF 导出/覆盖导入回归通过，覆盖前新增安全快照且列表即时刷新。测试数据已删除，用户原 9 张图纸内容哈希与色板状态完全一致。

## 自定义色板（0.6.20）

- 色板页顶部新增「导入色板」：用系统文件选择器（SAF）选一个 CSV，先预览标题和识别到的颜色数，确认后创建自定义色板并自动切换过去。全程离线，不申请存储权限。
- CSV 格式：带表头时色号列认 `色号 / 编号 / 颜色编号 / code / color / colorcode`，颜色列认 `hex / 颜色 / 色值 / 颜色值 / colorhex / rgb`；没有表头时默认「第一列色号、第二列 HEX」。支持逗号或制表符、带引号的单元格、BOM 和 CRLF；编码先严格 UTF-8，失败回退 GB18030；文件上限 2 MB、最多 500 色。
- 校验：色号允许中英文、数字、`_`、`-`，统一转大写；HEX 补成 `#RRGGBB`；重复色号和非法颜色计入无效行；没有可导入色号时直接提示。预览里可以改色板名，确认后写入 `filesDir/palettes/<id>.json`（`{id,title,groups,colors:[{code,hex,g}]}`，与内置色板同构）。
- 自定义色板和内置色板共用一套逻辑：当前色板、每色「我有/没有」、长按库存、颜色校准都按 `paletteId` 分开保存；图纸 JSON 里只记色板 id 与色号下标，编辑、缩略图、详情、导出、施工都按图纸自己的色板取色。
- 删除自定义色板：自定义色板被选中时色板条最右出现「删除此色板」。有图纸正在使用就只提示数量、删除按钮置灰；没有使用才可删除，同时清掉该色板的校准、库存和开关记录；如果删的是当前色板，自动切回 MARD 221。
- 单张图纸分享：自定义色板的图纸在 `.json` 里额外带 `palette` 对象（完整颜色表）。对方导入时优先按 id 复用本地色板；没有同 id 但颜色完全一致的自定义色板也直接复用；都没有就自动创建一份并提示「同时导入色板」，然后把图纸的 `paletteId` 重映射到本地新 id，格子下标不变。内置色板不内嵌。
- 整库备份升级到格式 2，带 `palettes/` 与 `paletteCount`；合并/覆盖规则、v1 兼容见上一节。快照同样会感知色板文件的改动。
- 模拟器验证：5 色 CSV 导入后生成 `files/palettes/custom-mvl8daef.json` 并自动切换，副标题显示「自定义 · test-palette」，单色开关重启后保持；用该色板新建 5×5 空白图画 5 格，图纸 JSON 为 `"paletteId":"custom-mvl8daef"`；有 1 张图纸使用时删除被拦截，另建一个未使用色板可删除并回落到 MARD 221；导入带内嵌色板的分享文件后新建 `远程色板` 并把图纸色板 id 重映射过去；实际生成的分享 JSON 经 `run-as` 确认同时包含 `paletteId`、`palette` 与完整 `pattern`；导出备份 manifest 为 `format=2, paletteCount=2`，覆盖恢复后 2 个色板、当前色板 `custom-mvl8daef` 与图纸全部回来；v1 旧包合并导入新增 1 张。测试后已把 App 数据恢复到测试前，9 张原图纸与备份 tar/原快照逐字节一致、施工进度仍为 1/1743、无残留自定义色板。真机微信/QQ 接收带色板 `.json` 也已验证通过。

## 照片误判修复与大图采样（0.6.21）

- 普通照片不再被认成「满格网格」。旧算法只要边缘能量自相关能找到 2–3px 的周期就接受，平滑渐变的照片几乎必然满足，于是输出 240×240，预览要画 57600 个方块，拖参数直接卡死。现在叠加四道闸门：
  - 周期 < 3px 直接拒绝（拼豆截图一格通常远大于 3px）；
  - 算出的格数 > 240 直接拒绝，不再截断成 240（那会把照片伪装成一张 240×240 图纸）；
  - 边界能量集中度 < 1.5 拒绝：真实网格的边缘集中在周期性边界列上（实测 3 以上），照片的边缘摊在每一列（实测 1.0–1.2）；
  - x / y 周期差超过 1/4 格拒绝。
  - 识别失败就正常退回「长边格数」（29 / 57），界面提示「没认出原图格子（大概是照片）」。
- 大图识别不整张取像素：裁剪区超过 1024×1024 时，只在中心 + 四角五个 1024 窗口里找周期，再把窗口相位换算回整张裁剪区、按整张尺寸重算格数。
- 取色采样按输出格数自适应：每格最多 8×8 个采样点（绝对上限 2M 像素）；裁剪与缩放用一次 `createBitmap(..., matrix)` 完成，不再先复制一张全尺寸裁剪图。4096×3072 照片拖尺寸滑块不再 OOM，模拟器 `gfxinfo` 的掉帧率从约 56% 降到约 7%，色数与豆数基本不变（狗图 1461 vs 1463 颗，差 0.1%）。
- 验证：4096×3072 平滑照片 → 29 格 + 退回提示，反复拖尺寸/色数滑块、拖裁剪角均不崩；1440×3200 像素画截图 → 51–52×119 格、27px 一格，预览与吸附正常；测试图片已清理，9 张原图纸、MARD 221、施工进度 1/1743 与快照未变。用户随后自装 0.6.21 到真机，按同一组项目复测通过。

## 缩略图缓存（0.6.3）

- 库页缩略图不再每帧重画所有格子：`data/PatternThumbCache.kt` 按「尺寸 + 色板 + 色板颜色指纹 + cells 内容哈希」渲染一次 256px 位图，内存 LruCache（8MB）+ `filesDir/thumbs/<id>-<尺寸>-<色板>-<指纹>-<哈希>.png` 双缓存，之后滚动直接贴图。
- 施工打勾只改 `updatedAt`，cells 哈希不变，所以不会重建缩略图；编辑、去杂点、减色、画布变换改了内容会自动换新 key，并清掉同一张图纸的旧文件；色板校准改了颜色会换指纹，旧缓存自动失效、显示时懒重建。
- 删除图纸时一起删缓存；没显示过的图纸不预生成，滚到哪生成到哪。
- 启动清扫（0.6.24）：首帧贴图前 `PatternThumbCache.sweep` 按 `data/ThumbCleanupPolicy.kt` 扫一遍 `files/thumbs`——图纸已不存在的孤儿文件、不合命名约定的残留直接删；同一张图纸只留最后修改时间最新的一份（时间并列留文件名字典序最小），旧指纹/旧内容哈希不再依赖"下次打开才清"。缓存可再生，删错最多重画一次。

## 非整数网格与照片取色（0.6.25）

- 网格周期细扫：`data/PixelGrid.kt` 的整数自相关峰连同它的 1/2、1/3、1/4 谐波一起进候选，每个候选在 ±1px 内以 0.05px 步长细扫，用「插值边界能量均值 × 覆盖率」打分，分数接近最高分里取最小周期（真基频优先）。3.3px、8.5px 一格的合成图实测精确命中「3.3×3.3px 一格 · 40×30 格」「8.5×8.5px 一格 · 30×24 格」，8.5px 保存后 6 色与合成完全一致；照片防误判门禁（整数峰 ≥3、置信度、边界能量集中度、格数上限）原样保留，纯色块图与 1200×1600 照片仍走「没认出原图格子」fallback。已知边界：3.3px 一格且每格带 1px 硬描边的极端合成图约 8% 格采到描边灰（格心区域太窄），真实缩放截图无此问题。
- 校准「从照片取色」：`data/ColorPick.kt` 纯逻辑（ARGB→6 位 HEX、ContentScale.Fit 点击坐标→原图像素，留边 clamp 到边缘像素）；色板长按 → 校准 → 从照片取色，PhotoPicker 选图（免权限），大图先缩到长边 1024px，点图回填 HEX，保存后「校」角标 / 「校准 N 色」/ 库页缩略图跟着变色，恢复默认复原。装机走查：点蓝块回填 0000FF、点留边 clamp 不崩、旋转屏幕不崩（弹窗随配置变化关闭属已知限制）、`files/palette_calibrated.json` 写入与清空均正确。

## 已踩过的坑

1. **工程路径含中文**：AGP 默认拒绝非 ASCII 路径，`gradle.properties` 里加了 `android.overridePathCheck=true`，构建/安装/运行均正常。
2. **Compose 编译器插件**：AGP 9 内置 Kotlin 2.2.10，只需额外应用 `org.jetbrains.kotlin.plugin.compose`，**不要**再应用 `org.jetbrains.kotlin.android`（会报 extension 冲突）。
3. **PowerShell 5.1 写文件会毁中文**：`Get-Content`/`Set-Content` 默认按 ANSI 处理无 BOM 的 UTF-8，改 Kotlin 源码请用编辑器工具或 Python，别用 PS 的读写往返。
4. `adb exec-out screencap -p` 在 PowerShell 里必须走 `cmd.exe /c "... > file.png"`，否则二进制被破坏。
5. **裁剪手势会被外层 scroll 抢走**：图片转图纸页改成「上方固定裁剪区 + 下方可滚动参数区」，裁剪框独占手势才拖得动。
6. **pointerInput 不会因参数变化重启**：`CropView` 里必须用 `rememberUpdatedState(rect)` 取最新裁剪框，否则每次拖拽都以初始整图框为基准，表现为"怎么拖都只动一点点"。
7. **`Bitmap.createBitmap` 裁剪整张图时原样返回 source**：这时 `recycle()` 会把界面上正在画的 bitmap 回收，崩在 `Canvas: trying to use a recycled bitmap`。只在新建的 bitmap 上回收。
8. **颜色下标映射别混用**：保留色集合里存的是「候选下标」，改投时不能再拿它当「第几个保留色」用，否则整张图会变成色板开头那几种颜色（表现为图案全是米黄/橘色）。
9. 系统返回键要显式接管（`BackHandler`），否则在详情页按返回会直接退出 App。
10. **平均色是像素画的敌人**：整图缩放 + 每格平均，会把 1px 的轮廓线摊成一片灰（这正是「细小处出现异常灰色色块」的来源）。改成每格取主色后消失。同时别指望"按用量取前 N 色"能自动省色号——色板里有十几个几乎一样的白，它们会占满预算。
11. **读图上限别设太小**：`loadBitmap(..., 2000)` 会把 1440×3200 的截图砍成 720×1600，网格识别精度直接减半。现在用 4096。
12. **给文件夹里加了文件，`adb shell am broadcast MEDIA_SCANNER_SCAN_FILE` 未必生效**（Android 14+ 只认媒体服务自己扫出来的）。往相册塞测试图时，用相机/下载目录并重启相册 App 更稳。
13. **绝对不能用 -1 当"透明/无效"哨兵**：纯白 `#FFFFFF` 的 Int 值正好是 -1，于是整片纯白（白底、白毛、白色豆子）被当成透明空格丢掉，表现为"空像素入侵图形"。取色函数的哨兵一律用 0；色板查色也要判 `== 0` 而不是 `== -1`，否则白色背景会被当成"无效色号"直接跳过整个功能。
14. **整格平均取色会带回灰边**：像素画截图经过缩放，格子边界一两圈是混合色，必须取格心（`INSET_RATIO = 0.18f`）再统计主色。
15. **吸附必须用「当前这块裁剪区」算出来的网格**：网格相位是相对裁剪区的，拿旧网格去吸附新框会把裁剪框压成一条细缝，还会误判出 2px 一格的鬼网格。现在用 `gridCrop` 记住网格对应的裁剪区，不一致就不吸附。
16. **吸附要有防呆**：四边夹进 [0,1]、保证至少 1.5 格宽高，且和用户框的尺寸差超过 2 格就放弃吸附（相位不可信），否则会出现零宽框。
17. **ARGB 颜色不能拿 `< 0` 当无效哨兵**：不透明色的 `0xFF……` 在 Int 里都是负数，去杂点曾因此把所有颜色当成无效、永远提示「没有找到杂点」。判断「查不到颜色」要用可空类型或 0，不能用负数。
18. **手势回调里别读组合期算好的派生 `val`**：`pointerInput(Unit)` 的回调可能一直持有旧闭包；`val currentBoard = highlight.coerceIn(...)` 这种值会停在创建时的板号，而直接读 `boardSpan` 的 state 又是新值，结果一半新一半旧。0.6.17 按板视图因此出现「切到 58 板后仍按 29 板过滤」；把板号、板数都改成在 `fun` 里现算才对。
19. **识别失败不能把格数截断到上限**：照片被误判出 2px 周期时，旧代码把格数 `coerceIn(2, 240)`，等于把照片伪装成一张 240×240 图纸，预览要画 57600 个方块，直接卡死。现在超过 240 格判失败，并加最小周期 3px、边界能量集中度 ≥1.5 两道闸门。
20. **取色别按原图分辨率整张读像素**：4096×3072 的 `IntArray` 是 50MB，模拟器 192MB 堆实测直接 OOM。按输出格数自适应采样（每格 8×8、绝对上限 2M 像素），裁剪+缩放用一次 `createBitmap(..., matrix)` 完成，别先裁剪再缩放。


## 豆仓库存（M5）

拼到一半发现白豆不够，是最常见的翻车点，所以有了这个。

- **记录**：色板页**长按色块** → 库存对话框里填你手上有多少颗（`不追踪` 可以清掉），同一个对话框也能进颜色校准。色块下面会显示数量，0 显示红色的「缺」。
- **批量导入**：色板页顶部「批量导入 CSV」，按「色号,库存」两列一次记完整箱豆子；先预览再写入，未识别色号会列出来。格式与验证细节见「库存批量导入（0.6.15）」。
- **拼完扣减**：施工到 100% 会弹确认框，按用量扣已记库存的色号，不足扣到 0；每张图纸只扣一次。细节见「拼完扣减库存（0.6.16）」。
- **算缺口**：图纸详情页会自动比对——成本卡片里多一行红字「豆仓缺 1 色 / 共 72 颗（补货约 ¥1.44）」，色号明细里每个色号单独标「库存 100 · 缺 72」或「库存 500 · 够」。
- **关键设计**：**没记过数量的色号不算缺口**（返回 `null` = 不追踪）。否则第一次打开任何图纸都会满屏「缺货」，功能就废了。
- 数据存 `filesDir/inventory.json`，形如 `{"mard221":{"A19":100}}`；内部用 `SnapshotStateMap`，改完数量界面立刻刷新，不用手动重进。
- 跟色板开关是两套：开关管「出图时能不能用这个色号」，库存管「够不够拼」。
